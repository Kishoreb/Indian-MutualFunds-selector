### rules
State: observed
- Summary:
  - Column mapping: spec columns are converted to toolkit units by fixed factors (e.g. `return_3y` times 0.01 becomes `cagr_3y`). Only `benchmark_excess_return` is ambiguous between styles.
  - Validation (nothing is repaired or guessed): blank/NA cells are MISSING; non-numeric or out-of-range values are INVALID (treated as missing, fund flagged). Range checks are hardcoded (e.g. `cagr_3y` in [-1.0, 10.0], `max_drawdown` in [-1.0, 0.0], `portfolio_quality` in [0, 100]). A real 0 is valid.
  - Duplicates: identical rows are dropped. Same name with different data is kept and flagged `DUPLICATE_NAME`. Rows with no fund name are rejected.
  - Plan filter: rows that are not Direct + Growth (when `plan_type`/`option` columns exist) are rejected unless `--include-all-plans`.
  - Staleness: `data_checks.check_table` flags stale dates. Per `config.EXCLUDE_STALE_FUNDS`, stale funds are excluded. Dates after `--as-of-date` are excluded.
  - Ranking: funds are ranked within their `fund_category` using `scoring.score_and_rank` (same scoring engine as `shortlist.py`). A category with fewer funds than `min_group_size` gets `LOW CONFIDENCE`. A fund below `MIN_SCORE_COVERAGE` is `INSUFFICIENT_DATA`. `expense_ratio` is present but explicitly not scored.
  - Exploratory: `--exploratory` pools all categories and re-ranks them together (labelled "EXPLORATORY").
