### rules
State: observed
- Summary:
  - Fund lookup: if the query is all digits, it looks up by scheme code. Otherwise, name tokens are extracted (dropping words like "direct", "plan", "growth", "fund"), and every Direct-Growth scheme whose tokens contain all query tokens is a match. The query words without spaces are also tried against the joined tokens, so "midcap" finds "Mid Cap". If multiple schemes match: exact-token matches are preferred; then stale twins (NAV older than 30 days from the newest) are dropped; then schemes with 2 ISINs (IDCW mislabelled Growth) lose. If still ambiguous, the user gets a list of up to 15 schemes with their codes. If no match, fuzzy suggestions above 50% similarity are shown. Regular-plan-only matches are explained.
  - Peer pool: all open-ended Direct-Growth schemes in the same normalised AMFI category with a current NAV, capped at `MAX_FUNDS_TO_SCAN` (60, alphabetically). Stale peers are dropped with a note. The target fund is always in the pool.
  - Evaluation: `shortlist.build_metrics_table` computes metrics for all peers. `shortlist.apply_hard_filters` checks whether the target passes the shortlist filters. `mf_holdings_screener.rank_peers` ranks the target among peers. `mf_holdings_screener.decide` produces the screen verdict (same rules as F005: CONTINUE, WATCH, MIXED, CONCERNS, INSUFFICIENT DATA).
  - Comparison table: 16 metrics are shown in order, each with the fund's value, peer median, "better than x% of peers" (direction-aware for volatility, beta, downside capture, drawdown), and the weight from `weights.ini`.
  - Peer eligibility: categories in `PEER_CATEGORY_KEYWORDS` (from S05). Index, sectoral, thematic and debt funds are not eligible; they are judged on benchmark and absolute returns only.
